# Cascade Hunter — Final-2

محاكاة ورقية مستقلة ببيانات Binance USDT-M الحية، دون مفاتيح أو أوامر حقيقية. تحديث 30 أكتوبر 2026: وقف 5%، تعزيز واحد عند 2.5% بقيمة الدخول الأولى، هامش أولي 5%، وحتى 5 مراكز. التعديل يخص Final-2 فقط.

## الإعدادات الحالية

| الإعداد | القيمة |
|---|---|
| المحفظة الابتدائية | 100 USDT للجلسة الجديدة |
| هامش الدخول الأول | 5% من رصيد المحفظة الحالي قبل رسوم الدخول |
| الرافعة | 50× كما كانت |
| أقصى عدد مراكز مفتوحة | 5 |
| وقف الخسارة الأولي | 5% من **سعر التنفيذ الأول**، شراء أو بيع |
| التعزيز | مرة واحدة عند انعكاس السعر 2.5% من **التنفيذ الأول** |
| قيمة التعزيز الاسمية | 100% من القيمة الاسمية للتنفيذ الأول |
| تفعيل جني الربح المتحرك | 1.8% من متوسط الدخول الحالي كما كان |
| مسافة وقف الربح | 0.9% خلف أفضل سعر مرصود كما كانت |
| خطوة تمديد الهدف | 0.5% من متوسط الدخول كما كانت |
| الرسوم | 0.05% لكل تنفيذ بما فيه التعزيز والخروج |

«نفس الحجم» هنا يعني نفس **القيمة الاسمية بعملة USDT**، وليس عدد العملات نفسه: يُحسب عدد العملات من السعر الراهن ثم يقرب وفق السوق. عند محفظة 100 USDT يكون الهامش الأول نحو 5 USDT والقيمة الاسمية نحو 250 USDT. التعزيز يستهدف نحو 250 USDT أيضًا، بهامش نحو 5 USDT إضافية؛ إجمالي هامش المركز بعده يقارب 10 USDT قبل فروق التنفيذ والتقريب. 5% تخص الدخول الأول ولا تشمل التعزيز لاحقًا.

الوقف لا يعاد حسابه من المتوسط بعد التعزيز. مثال شراء بتنفيذ أول 100: تعزيز عند 97.5 ووقف ثابت 95. مثال بيع: تعزيز عند 102.5 ووقف ثابت 105. إذا قفز السعر مباشرة إلى الوقف أو تجاوزه، الخروج أولًا دون تعزيز. التعزيز المرفوض لا يعد منفذًا ويمكن إعادة محاولته، والمنفذ يحفظ ولا يتكرر بعد الاستئناف.

يُحدث متوسط الدخول بعد التعزيز ويصبح مستوى تفعيل الملاحقة 1.8% من المتوسط الجديد. عند بلوغه لا تغلق الصفقة مباشرة؛ يتفعل وقف الربح على مسافة 0.9% من أفضل سعر ويتحرك باتجاه الربح فقط. يمدد مؤشر الهدف بخطوات 0.5%، والخروج عند الوقف. لا تعزيز بعد تفعيل الملاحقة. مراقبة الخروج كل 8 ثوانٍ تقريبًا؛ قد تختلف أسعار التنفيذ عن مستويات الرصد.

شروط الإشارة الأصلية محفوظة: حركة تتجاوز ±1.2% خلال دقيقتين، حجم يتجاوز 3.5× المتوسط، وضغط دفتر يتجاوز ±0.35 في الاتجاه المناسب. أعلى 40 عقدًا مؤهلًا بالسيولة، وتحديث القائمة كل 600 ثانية، وفحص مستمر بتحديثات WebSocket.

## تشغيل الريبو على أوبونتو داخل تيرمكس

Python 3.11+ مطلوب. بعد تنزيل الريبو:

```bash
cd ~/Final-2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -u cascade_final2_paper.py
```

ملف الحالة الافتراضي `paper_state_final2.json` يستأنف تلقائيًا إذا طابقت إعداداته. Ctrl+C يحفظ الحالة. لا تشغّل عمليتين على الملف نفسه. لا تستخدم `--reset` للاحتفاظ بجلسة سابقة؛ لإنشاء جلسة منفصلة مع حفظ القديمة استخدم مسار حالة جديدًا:

```bash
python -u cascade_final2_paper.py --state paper_state_final2_risk_v2.json
```

## تحديث جلسة موجودة دون حذفها

ملفات حالة النسخة السابقة غير متوافقة مباشرة لأن الوقف والتعزيز والحجم وعدد المراكز تغيرت. أوقف البوت قبل أي تعديل على الحالة.

إذا لم توجد مراكز مفتوحة، يمكن ترحيل إعدادات الجلسة مع حفظ رصيدها وكل التنفيذات السابقة. الأداة تتحقق من إعدادات النسخة السابقة المعروفة، وتنسخ الأصل احتياطيًا قبل الكتابة:

```bash
python migrate_idle_state.py paper_state_final2.json
python migrate_idle_state.py paper_state_final2.json --apply
```

الفحص الأول لا يكتب. الثاني يحفظ نسخة `.bak` بجانب الملف ويغير إعدادات المستقبل فقط. نتائج الصفقات القديمة لا يعاد حسابها؛ الجلسة بعد الترحيل تحتوي تاريخ الإعدادات السابقة ونتائجها ثم التنفيذات الجديدة. احتفظ بالنسخة الاحتياطية للمقارنة.

إذا توجد مراكز مفتوحة، يرفض الترحيل ولا يغيرها. أكمل إدارتها تحت النسخة السابقة أولًا، أو ابدأ جلسة جديدة منفصلة بالمسار أعلاه واحتفظ بالحالة القديمة. لا تنقل مركزًا مفتوحًا تلقائيًا إلى وقف جديد.
