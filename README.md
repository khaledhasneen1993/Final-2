# Cascade Hunter — Final-2

نسخة ورقية مستقلة مبنية على النسخة الأساسية من `khaledhasneen1993/Final` عند commit `594af2520efdb1d87f4da2d8e70ae1144556f46a`. لا تغيّر المستودع الأصلي، ولا تستخدم مفاتيح Binance أو تنفذ أوامر حقيقية.

## الإعدادات

- محفظة ابتدائية 100 USDT، هامش دخول 10% من المحفظة الحالية، رافعة 50×، أقصى 3 مراكز مفتوحة.
- متابعة مستمرة لنفس إشارات الحركة والحجم وضغط دفتر الأوامر؛ أعلى 40 عملة مؤهلة وتحديث قائمة السيولة كل 10 دقائق.
- وقف الخسارة الأولي 15% من **سعر الإشارة الأول**؛ لا يُبعد ولا يعاد حسابه بعد التعزيز.
- تعزيزان فقط، عند انعكاس السعر 5% ثم 10% من **سعر التنفيذ الأول** في اتجاه الخسارة، وليس خسارة الهامش أو الحساب.
- قيمة كل تعزيز: نصف القيمة الاسمية للدخول الأول. دخول أصلي بـ500 USDT يعني تعزيزين مستهدفين بـ250 USDT لكل منهما، بهامش نحو 5 USDT لكل تعزيز عند 50×. يُحسب الحجم من السعر الراهن ثم يُقرّب؛ سعر التنفيذ الفعلي قد يختلف.
- يظل التعزيز داخل المركز نفسه ولا يستهلك خانة مركز جديد. يخضع للحد الأدنى والأقصى للسوق وكفاية الرصيد والهامش وقيمة المحفظة الحالية.
- بعد التعزيز يُحدث متوسط سعر الدخول الموزون والحجم، ويعاد هدف 1.8% من المتوسط الجديد.

## جني الربح المتحرك

لأن مسافات التحريك لم تُحدد في الطلب، تعتمد النسخة هذه القيم القابلة للتعديل أعلى `cascade_final2_paper.py`:

1. هدف 1.8% من متوسط الدخول هو **مستوى تفعيل الملاحقة**. عند بلوغه لا تُغلق الصفقة مباشرة.
2. يصبح وقف الربح على مسافة 0.9% خلف أفضل سعر مرصود: أسفل القمة للشراء، وأعلى القاع للبيع.
3. يُنقل الهدف إلى النقطة التالية بخطوات 0.5% من متوسط الدخول؛ الهدف المتحرك مؤشر، والخروج الفعلي عند لمس الوقف.
4. وقف الربح يتحرك باتجاه الربح فقط، ولا يتراجع إذا تراجع السعر. لا تعزيز بعد تفعيل الملاحقة.

مثال شراء بمتوسط 100: عند 101.8 تُفعل الملاحقة، يصبح الوقف 100.8838 والهدف التالي 102.3. عند 105 يصبح الوقف 104.055 والهدف التالي 105.3. إذا تراجع السعر إلى الوقف يُغلق المركز افتراضيًا. المراقبة كل 8 ثوانٍ، وقد يتجاوز السعر مستوى الوقف أثناء الفجوات؛ الربح المحقق غير مضمون.

إذا قفز السعر عبر مستوى التعزيزين دون بلوغ الوقف، تُحاول النسخة تنفيذهما بالسعر الحالي بالتتابع. إذا وصل مباشرة إلى الوقف، تُغلق الصفقة أولًا دون تعزيز. التعزيز المرفوض لا يُحسب منفذًا ويُعاد فحصه في دورات لاحقة؛ التعزيز الناجح يُحفظ ولا يتكرر بعد إعادة التشغيل.

## التشغيل على أوبونتو داخل تيرمكس

```bash
git clone https://github.com/khaledhasneen1993/Final-2.git
cd Final-2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -u cascade_final2_paper.py 2>&1 | tee -a final2-paper.log
```

Python 3.11 أو أحدث. هذا الأمر يستعيد `paper_state_final2.json` تلقائيًا؛ لإجراء تجربة مستقلة مع حفظ السابقة:

```bash
python -u cascade_final2_paper.py --state paper_state_final2_trial2.json
```

الإيقاف بـ Ctrl+C يحفظ الحالة. لا تستخدم `--reset` إلا لبدء محفظة جديدة بدل حالة الملف المحدد. ملف الحالة يحفظ جميع التنفيذات، والتعزيزات ومستوياتها، ومتوسط الدخول، وأفضل سعر، والوقف المتحرك وسبب الإغلاق (`SL` أو `TRAIL_SL`). الرسوم الافتراضية 0.05% لكل تنفيذ، بما فيه كل تعزيز. تُرفض حالة V2 القديمة بسبب اختلاف إعدادات النسخة.

ملفات V2 الموجودة وحدات دعم موروثة؛ نقطة تشغيل هذه النسخة هي `cascade_final2_paper.py` فقط. ترسل هذه النسخة بيانات المراقبة اختياريًا إلى اللوحة الموحدة عند ضبط متغير البيئة المحلي `CASCADE_DASHBOARD_TOKEN`. تظهر التعزيزات كتنفيذات مستقلة مرتبطة بالجلسة والمركز، ولا تتغير آلية التعزيز أو وقف الخسارة أو جني الربح بسبب هذا التكامل. لا تحفظ الرمز في Git أو ملفات المشروع المتتبعة.
